02 — overview

What is Design System Guard

Design System Guard is an agentic Figma plugin that continuously scans design files, validates components against the library, checks for hardcoded tokens, and runs a heuristic validator powered by Claude — then posts a structured diff report directly to Slack and exports Maestro test scripts.

The goal was to close the gap between what designers specify and what reaches the end user — a gap that was growing silently sprint over sprint, and was only discovered at QA or in production.

03 — context & problem

Three problems we couldn't ignore

The Cora design team had a widening gap between Figma specs and what reached the client — caused by silent detachments, ignored tokens, and test scripts that only covered happy paths.

PAIN_01

Silent detachments

Components copied and modified directly on canvas without keeping the library instance. The error was only found at code review or in QA — post-sprint.

Late discovery
PAIN_02

Hardcoded tokens

Colors and spacing inserted as absolute values out of habit or urgency. Without Design System variables, any identity change triggered cascading rework.

Recurring rework
PAIN_03

Incomplete test scripts

Maestro covered happy paths only — missing error states, empty states, edge cases. The same gaps that appeared as production bugs weeks later.

Insufficient coverage
04 — the pipeline

Four steps, fully automated

The Guard runs before every handoff. Critical issues block the export; warnings are logged in Supabase with full traceability. Designers ship more, reviewers catch less.

STEP_01
Figma API scan
Full file traversal via REST. Extracts component instances, variable bindings and layer structure into a normalised diff payload.
STEP_02
Diff detection
Compares current state against the last validated snapshot. Flags detachments, hardcoded values and structural changes since last export.
STEP_03
Heuristic validation
Claude analyses flagged screens for missing error states, CTA inconsistencies, copy variance and accessibility heuristics — before any human sees it.
STEP_04
Report + Maestro export
Structured Slack message posted to #design-updates. Test script generated for Maestro, covering all detected edge cases and error scenarios.
05 — delivery quality

Closing the Figma → production gap

The divergence between what a designer specifies and what ships is a rarely measured metric — with direct impact on experience and team confidence.

DETACHED_COMPONENTS / DELIVERY

Accidental detachments

8.4 → 3.1 −63%

Automatic detection in the plugin makes the designer fix before handoff. The number never reaches zero — new components legitimately enter as frames — but accidental detach rate dropped 63%.

HARDCODED_TOKENS / SCREEN

Hardcoded values

11.2 → 4.7 −58%

Deterministic validator flags colours and spacings outside variables in seconds. Remaining hardcodes are mainly in flows still in progress.

USABILITY_BUGS / SPRINT

Bugs caught late in QA

14.6 → 9.0 −38%

Heuristic validator catches 38% of bugs that previously only surfaced at QA or in production. A Figma-stage bug costs 10–20× less than a prod bug.

FLOW_INCONSISTENCIES / FLOW

Cross-screen inconsistencies

6.3 → 2.8 −56%

Multi-screen validator detects CTA position shifts, copy variation and inconsistent interaction patterns between steps — issues that previously only showed up in user testing.
