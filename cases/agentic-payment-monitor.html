02 — overview

What is Design Weekly Reporter

Design Weekly Reporter is an AI-powered agent that autonomously aggregates data from four sources — Slack, JIRA, Figma and Google Calendar — processes it through Claude API, and generates a structured design report every week, delivered directly to the team's Slack channel.

The agent runs on a cron schedule (Mondays, 10:30 AM) via Vercel Functions. When uncertain about context, it sends a validation DM before posting publicly — keeping the team in control without adding manual work.

03 — context & problem

Status scattered across four tools

The Cora design team was managing 5 concurrent initiatives across Coraliados and partnership products. Progress updates lived in Slack threads, JIRA tickets, Figma version history and meeting notes — never in the same place.

Every Monday, synthesising that data into a coherent executive report required 30+ minutes of context-switching and manual aggregation. The result was inconsistent coverage, missed blockers, and leadership often acting on stale information.

04 — data sources

Four inputs, one coherent signal

The agent reads from all four sources concurrently before aggregation begins — ensuring no signal is dropped and cross-source context is preserved.

SOURCE_01

Slack

Last 7 days of #updates-design and #coraliados-oneteam. Extracts progress mentions, blocker signals, and decision context from thread replies.

7 day window · 2 channels
SOURCE_02

JIRA

Five active initiative tickets (SP-3293, SP-3513, SP-3284, SP-3703, SP-3359). Reads status, comments, and recent updates via REST API.

5 tickets · status + comments
SOURCE_03

Figma

Three design system files. Maps component updates, variant changes, and last-modified timestamps to detect active design work.

3 files · version history
SOURCE_04

Google Calendar

Meeting titles, descriptions and participants from the past 7 days. Extracts decisions documented in event details and follow-up notes.

7 day window · decisions
05 — the pipeline

Aggregate → synthesise → deliver

The pipeline runs end-to-end in under 90 seconds. If Claude's confidence falls below threshold on any initiative, a validation DM is sent before the public report posts.

STEP_01
Concurrent fetch
All four APIs called in parallel. OAuth 2.0 for each. Raw payloads normalised into a unified JSON structure before aggregation.
STEP_02
Data aggregation
Messages, tickets, file diffs and calendar events merged. Keywords extracted, blockers flagged, cross-source connections mapped per initiative.
STEP_03
Claude synthesis
Claude API processes the aggregated context. Generates [DESIGN-UPDATE] format per initiative — advances, blockers, stakeholder impact and business metrics.
STEP_04
Validate + deliver
Optional validation DM if context is uncertain. Final report posted to #updates-design — same format, same time, every Monday.
06 — report format

Executive-ready by default

Each initiative is reported in the same structured format — combining data from all four sources into a context-rich summary that leadership can act on without follow-up questions.

[ DESIGN-UPDATE ] · template
Initiative {name}
Objective {brief_synthesis — Claude-generated from cross-source context}
Link JIRA {ticket_url}
Link Figma {design_file_url}
Progress {weekly advances + decisions — from Slack, JIRA, Calendar}
Experience impact {user impact + business metrics}
Urgent requests {blockers or none}
07 — implementation

Serverless, scheduled, self-correcting

Built as a serverless agent deployable to Vercel. The React dashboard allows manual overrides and trigger runs outside the Monday schedule. The Node.js worker processes all four APIs concurrently, reducing total fetch time to under 30 seconds.

Deployment via GitHub → Vercel CI. Cron jobs scheduled through Vercel Functions. Each component is independently restartable — if one API fails, the rest of the report still runs with a flagged gap rather than no report at all.
